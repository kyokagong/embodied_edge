# SuperMimic 一键站立与实机日志

日期：2026-11-07。模型、Rust ROS2 SDK、ONNX Runtime、Web/API及实际HAL发布均在Q1。本体地址：<http://192.168.54.41:8768>。Mini PC负责开发、交叉构建和日志分析。

## 当前操作

无需操作口令，直接点击“一键站立”。页面自动连接控制器、读取真实姿态、处理可复位的旧保护状态，再发起一次站立任务。站立后可以选择舞蹈并播放，取消后平滑返回站立。

任务在Q1上执行：实测姿态接管约3秒、约20秒的平滑初始站姿过渡、渐入零速度模型保持。固定站立任务由一次明确启动授权，浏览器心跳用于新的控制请求仲裁，不作为起身动作的持续许可。停止和解除接管始终是显式操作。

“停止并保护保持”捕获当前实测姿态；“解除接管／回到自然姿态”清除位置接管，输出零刚度、最高0.5的低阻尼，不切断电机电源，也不重设编码器零位。每次新的站立都从当时真实测得的关节角开始。

当前按用户要求采用 **50Hz实际HAL下发** 进行功能验证。独立本体监测线程仍按2ms调度，ROS2反馈持续读取；执行器不再接收500Hz的重复目标。`q1-rt`命令行默认发布频率为500Hz，本次本体入口显式传入 `--publish-hz 50`。本次50Hz试验不等同于完成500Hz控制验收。

## 模型动作与保持发布

本模型输入为 `[1,1376]`，输出为 `[1,22]`，每20ms给出一组22关节目标，不输出未来10步的action chunk。输入的10帧历史与500Hz执行层的10个子周期不是同一概念；舞蹈分支的未来参考也不是动作输出。

500Hz时，在两个策略更新之间保持最近目标；50Hz时每个发布周期下发最近有效目标，由驱动器保持。均不把重复的绝对位置目标累计成额外关节位移。

限幅在不同层分别记录：

1. `candidate_raw`：ONNX原始输出。
2. `target.raw`：策略边界实际接收的raw，先取±20、最大纠正量及机械范围的交集。下一帧观测回填这一有效raw，尚未乘0.25/加home。
3. 目标位置：`home + 0.25 * effective_raw`，之后有起始渐入与目标斜率限制。
4. 实际HAL目标：RT层再施加位置纠偏、速度方向约束及PD力矩估算上限。不能把这个延迟后的电机目标反算值当成策略上一动作。

原有实现把限幅前模型输出回填，而实际目标被截断。真实记录曾出现raw持续增大到6～8、多轴长期限幅。修正策略边界后，首次50Hz记录中策略raw峰值约0.818，记录区间不再有策略幅度饱和。两项调整同时发生，不能仅凭这次试验断言发布频率是此前未站起的唯一原因。

单次没有新鲜模型结果时，页面显示“等待下一帧有效模型输出”，不重打时间戳、不发过期新动作。独立RT继续检查原目标的真实有效期；超过期限仍进入保护保持。非有限数据、真实反馈失效、过温和显式停止保留失效保护；动作幅度、跳变、跟踪和速度等按连续饱和约束处理。

## 日志与关联

日志为Q1上的私有JSONL，运行目录和写入／丢失计数可在 `/api/state` 中读取，页面显示计数。没有通过HTTP开放完整观测张量或日志下载。

|记录|内容|关联方式|
|---|---|---|
|`manifest.json`|模型SHA256、配置SHA256、实际限幅和增益、模型契约；RT记录固定HAL槽位|每次进程运行固定一份|
|Actor `input`|完整1376维输入、真实关节/IMU、上一有效raw、构造时间与源采样时间|`epoch`、`id`|
|Actor `inference`|原始22维输出、推理开始/结束、耗时|相同`epoch`、`id`|
|Actor `target`|模型观测ID、实际入列的raw与目标、限幅轴、阶段、已收到的真实HAL反馈|`observation_id`、`target.sequence`|
|Actor `event/state`|一键请求、复位、停止、解除接管、阶段变化和故障|单调时间、请求ID、epoch|
|RT帧|真实发布序号、采用的目标序号、实测q/qd/力矩/温度/IMU、实际下发q/Kp/Kd、PD估算、限幅位、时间间隔|`epoch`、`accepted`、`hal_sequence`|

RT记录的是实际发布周期：当前约50Hz，切回500Hz时按实际500Hz记录。`publish_interval_ms` 是真正的HAL发布间隔，`interval_ms` 是独立监测线程的间隔。二者分别统计。

Actor日志位于版本目录 `private/flight/actor-*/`；RT日志位于保护器目录 `state/flight/rt-*/`。当前实际路径由状态中的 `flight_log.directory` 与 `bridge.flight_directory` 提供。通过已有授权SSH读取。

日志文件0600、运行目录0700。写盘与JSON序列化在独立线程，控制线程用有界非阻塞队列提交；队列满、写盘失败都显示计数或错误。每条流循环使用8个64MiB文件；已停止的版本目录日志保留。失能空闲时降低日志密度，活动站立时保留逐帧记录。

## 统一模型新版两段视频：根因与解决方案

用户确认仿真与真机均为iteration22100、dance1_subject2。两段视频16.8秒及14.13秒没有可读同步控制台标记，不能逐帧绝对对齐。当前统一模型版本有三轮subject2：19:24:41播放18.145秒、19:27:20播放15.982秒、19:30:09播放13.173秒，均由用户取消；三轮逐一审计，不以手机创建时间强行配对。机器人当前已解除接管，本轮没有发送动作或改变参数。

### 已确认的软件问题

训练 `q1_unified_task.py::proprio` 使用 `env.action_manager.action`；统一任务clip_actions=20，上一动作应为送入action manager的raw裁剪±20值。当前部署 `supermimic/action.rs:17` 在机械位置裁剪后，用 `(q_bounded-home)/scale` 反算effective_raw，控制器再将它填回历史。因此部署虽内部自洽，却与训练的上一动作边界不一致。这是实际适配缺陷，而不是已证明的模型能力不足；先前仅比对部署自身Target.raw的检查遗漏了这一层。

三轮真实输入中，上述不一致分别554/908（61.0%）、183/798（22.9%）、65/658（9.9%）。逐帧goal SHA与subject2原始NPZ全部一致，1376维/mode、最新关节观测检查未发现错误。需要优先分开保存policy_raw=clip(raw,±20)与motor_safe_target；机械、速度、力矩裁剪仍可保留在执行层，但不应反算后污染模型previous-action历史。

### 执行和环境差异

三轮HAL均约50Hz，无舞蹈阶段保护故障；额外幅度盒子已经移除，纯力矩裁剪和速度减力均为0%。因此本轮不能继续归因于旧±0.25rad限制或力矩上限太小。上肢目标到实际平均误差约0.035～0.042rad；髋roll约0.246～0.380rad。髋关节上报力矩与RT估算平均值接近，未见整体十倍量纲错误的证据；不能据此认定全部驱动器标定完成。

低层仍有跟踪误差纠偏，三轮约37.8%/16.4%/8.3%的HAL帧涉及至少一轴，但其触发表示目标偏离反馈，不能单独证明它是初始失真的原因。关节机械位置边界也仍生效，应保留，不能通过继续删除保护来掩盖状态分布问题。当前脚踝Kd=2，训练模型中为0.8，也需实测响应辨识，不盲目修改。

视频可见吊带绷紧、身体受外部支撑约束，结合用户此前确认的悬空状态，不能视为正常地面支撑舞蹈。足底是否全程承重没有传感器证据。训练源码配置plane与足底接触；舞蹈reset直接写参考root状态、q、qd，运行中模型条件切换并不等价于这种仿真初始化。单模型有两个条件分支，不自动证明已学会任意实机站立→舞蹈转换。若继续吊装悬空，应将其定位为上肢/接口检查或专门训练固定基座任务，不能据此判定地面全身策略合格。

推理中位约11.6～11.9ms、最大约25.6～35.6ms；观测到HAL中位31～32ms、p95约54～57ms、最差约92ms。约7.1～7.8%的目标复用旧预测。训练执行器设置delay_min_lag=0、delay_max_lag=10，不能直接把该参数单位当成策略周期；必须结合所用mjlab实现确认。当前源模型physics_dt=2ms、control_dt=20ms。真实延迟及抖动应测量后纳入训练，不能只比较平均50Hz。

### 模型能力判定与修复顺序

1. P0修复上一动作语义：模型原生raw与电机安全目标彻底分开，日志同时记录两者。用真实已采集观测做回放，逐帧与训练定义一致；不删除机械/力矩/反馈保护。
2. P0数值复核：相同真实1376维输入送入源JIT与ONNX，对比raw输出。已有68组golden最大误差约1.07e-6，说明导出没有明显数值损坏，但不是实际观测回放或闭环质量验收。本轮开发容器没有PyTorch，因此未声称已完成真实观测JIT/ONNX复核；输入样本已私有保存，可在训练环境执行。
3. P1状态/执行器对齐：确认足底承重、吊带仅防倒；核验IMU→pelvis、初始航向与参考坐标、q/qd/驱动器增益响应。第三轮开始yaw差约20.7°，其他两轮约2.7°/4.3°，并非三轮共同唯一原因。先作受限辨识，不靠抬高力矩上限补偿。
